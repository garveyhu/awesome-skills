01 — 为什么

记忆不该锁在别人的黑箱里

大多数 AI 产品的 memory 是藏起来的：你不知道它记了什么，也不知道它为什么突然误解你；换个工具，一切清零。它的「懂你」是租来的，不是你的资产。

黑箱 memory

  • 改不动、删不掉
  • 绑死单一厂商，换工具归零
  • 突然误解你也无从排查

02 — 核心立场

Vault 是真理，
工具是可弃适配器

「不管 agent 工具怎么变」的全部秘密在一句话：把记忆和契约都放进 Vault；每个工具只给一个 5 行的 stub 指向它。换工具 = 重写 5 行，大脑分毫不动。

03 — 结构

五层 · 按生命周期切，互不重叠

沿用视频的五文件夹骨架，内核换成业界的记忆机制。每层职责单一，谁能写、写什么，边界清晰。

00-RULES身份层：我是谁 · 沟通风格 · 禁用词 · 跨领域铁律。最高法律，常驻注入每个会话。仅晋升 + 你审批
01-PROJECTS项目层：每项目一目录，内分 decisions(共同决定) + feedback(我打回的产出)；支持任意层级嵌套子项目。agent 可直接写
02-SOURCES资料层：爬回来的文章 / 工具 / vendor 文档（Web Clipper 一键转 md）。agent / 插件
03-MAPS图层：流程图 / 决策树 / 架构。讲半天不如扔一张图。agent / 你
04-FEEDBACK飞轮中枢：每日 journal + 蒸馏 candidates + 留痕 DREAMS。引擎 + 你审批

捕获 — 落进每日 journal

工作中的纠正、决策、偏好，agent 追加到 04-FEEDBACK/journal/今天.md（前缀 决策:/偏好:/纠正:）。上下文压缩前还会 auto-flush，先把要紧的抢救进 journal，防长会话丢记忆。

核心哲学：LLM 只负责「抽候选」和「用记忆」，绝不负责「决定什么进长期库」——打分、去重、晋升门全是确定性规则。记忆永不被模型幻觉污染。
05 — 蒸馏内部

六维加权打分，确定性把门

夜间脚本扫 journal + Claude/Codex 会话日志，给每条候选打分。达标的才进「待审批」，绝不直接改 00-RULES。权重借自 OpenClaw 的 Dreaming：

重复够了才进铁律

跨项目要进 00-RULES 的，必须重复 ≥2 次（min_freq_global）。偶发的一句话不会污染你的最高法律。

去重 / 冲突

ADD · UPDATE · NOOP

借 mem0 思路：新候选先和已有记忆比相似度——太像就标 UPDATE/NOOP，而不是又新建一条。

为什么内核不调 LLM？抽候选这步是可换的 CLI provider（claude / codex / gemini 等本地 CLI，可配主选 + 兜底），聪明但可替换、不占主力额度；而「决定记什么进长期库」交给确定性规则（可信、可审计、可回滚）。每次蒸馏都留痕 DREAMS.md，记忆怎么变的全程看得见。吸收自 open-second-brain：no LLM inside the algorithm, no surprise hallucinations in your memory。

06 — 使用方式

一天的样子（混合模式）

自动出草稿 + 你审批晋升。你只在最后一步花几分钟，其余自动转。

读 —— 已自动

照常用 Claude Code / Codex。它们已被 stub 配置成「答你的事先读宫殿、不瞎猜」。从下一个会话起、任何项目里都生效。

写 —— 随手记

跟 agent 说一句，或自己在 Obsidian 里写。落进 journal 或对应项目。

# 对 agent：
"把刚才的决定记进大脑" → 追加到 04-FEEDBACK/journal/今天.md

蒸馏 —— 夜间自动

cron 每晚 03:00 跑（用本地 CLI 抽候选，可挑额度宽的、不占主力），出候选到 candidates.md，绝不动 00-RULES。想先预览就 --shadow。

/memory-palace distill # 或 mp.py distill --vault <宫殿> · --shadow 干跑

审批 —— 你拍板

跑 /memory-palace review，勾选通过的候选，晋升进 00-RULES / 项目，留痕 DREAMS，git 可回滚。

/memory-palace review # 勾 [x] → mp.py promote 晋升 + commit
07 — 接缝

和你现有体系怎么共存

不造重复、不漂移。记忆宫殿只管「我这个人」，其余各归各位、互相指向。

现有资产处置为什么
工具自带的规则目录
(如 ~/.claude/rules)		可集中进宫殿 + 软链回去真身在 vault、各 CLI 共读一份；mp.py link 重建软链
skill / 插件系统各管各的，宫殿只链接不复制单一事实源仍是它们各自的注册表
已有的项目专属知识库留原地，宫殿放索引卡指过去成熟独立体系，吞并反而破坏它的单一事实源
工具自带的私有 memory
(如 ~/.claude/.../memory/)		降级为工具专属操作便签实质记忆一律进 vault，避免两套打架
