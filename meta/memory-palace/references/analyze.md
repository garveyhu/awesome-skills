# analyze — 体检宫殿，给整理优化建议

目标：扫用户现有宫殿，找出腐化点，给**可执行**的整理建议，确认后帮改。

## 步骤

1. **跑体检**：
   ```bash
   <SKILL_DIR>/scripts/mp.py analyze --vault <VAULT>
   ```
   它报告：缺 frontmatter、陈旧（`last_confirmed` > 180 天）、低置信、重复嫌疑（标题相似）、孤儿（无人 `[[wikilink]]` 指向）。

2. **结合内容判读**（脚本只给线索，你要读 note 才能下判断）：
   - **重复** → 该合并的合并成一条（保留信息量大的，`[[link]]` 另一条），别留两份。
   - **陈旧** → 还成立？成立就更新 `last_confirmed`；过时就标 `deprecated` 或删。
   - **低置信/草稿** → 值得升 high 吗？还是该让飞轮再攒证据？
   - **错层** → 工程规范躺在身份层、临时 todo 混进 00-RULES 之类，建议归位。
   - **缺 frontmatter** → 补 `type/scope/confidence/updated`。
   - **矛盾** → 两条记忆互相打架（如偏好冲突），指出来让用户裁决。
   - **结构** → 某层是否过载该再分子目录；项目层是否该用多级嵌套。

3. **出一份带优先级的建议清单**给用户（高/中/低），每条说清「问题 + 建议动作 + 影响」。

4. 用户挑要做的，**逐条确认后**帮改；改完可 `git commit`。

## 纪律
- 只提建议 + 执行用户点头的，不擅自重组用户的最高法律（00-RULES）。
- 删除/合并是有损操作，先确认、且 git 可回滚再动手。
