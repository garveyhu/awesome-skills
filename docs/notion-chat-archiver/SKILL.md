# Notion Chat Archiver

## 定位

把任意一次与 AI 的对话，结构化沉淀到 Notion 的**对话录库**数据库里。不是单纯的复制粘贴，而是做**摘要 + 分类 + 价值萃取**，形成可以长期复盘的知识资产。

## 设计思想

### 为什么要有对话录

AI 工具用多了会出现一个反直觉的问题：**聊得越多，能力提升越慢**。因为大多数对话结束后窗口就关掉了，那些本该被吸收的认知洞察和方法论随之流失。

对话录库解决的就是这个问题——**把一次性对话变成可复盘的知识资产**。

### 核心设计原则

1. **结构化 > 堆积** — 每条记录都有统一的元数据，支持按主题/时间/重要度检索
2. **摘要 > 全文** — 对话原文很长且有大量冗余，提炼核心收获和关键转折点才是精华
3. **价值分级** — ⭐⭐⭐ 只留给真正改变认知或决策的对话，避免库膨胀
4. **复盘闭环** — `是否复盘` 字段强制要求回顾，否则等于没存

### 数据库字段表

| 字段 | 类型 | 作用 |
|------|------|------|
| 标题 | title | 一句话定位这次对话（≤15 字） |
| 日期 | date | 对话发生的日期 |
| 主题 | select | 8 选 1：学习规划 / 职业发展 / 技术方案 / 产品设计 / 调试排错 / 认知思考 / 工具使用 / 其他 |
| AI 模型 | select | Claude Opus / Claude Sonnet / Claude Haiku / GPT-5 / Gemini / 其他 |
| 相关项目 | multi_select | AI Development / Skills / 个人成长 / 其他 / sage |
| 核心收获 | rich_text | 1-2 句话总结最有价值的点（检索时第一眼看的内容） |
| 标签 | multi_select | 方法论 / 架构设计 / 原理理解 / 工具链 / 人生决策 / 灵感 |
| 重要度 | select | `⭐⭐⭐ 高` / `⭐⭐ 中` / `⭐ 低` |
| 是否复盘 | checkbox | 默认 false，提醒回看 |
| 创建时间 | created_time | 自动 |

### 记录页面内容模板

元数据只是索引，真正的价值在页面内容里：

```markdown
> 完整对话见 @mention 或贴附件

## 一句话背景
为什么会有这次对话？触发点是什么？

## 关键收获
1. 最核心的认知洞察
2. 第二重要的方法论
3. 具体的决策或行动项

## 落地产出
- 如果有产出物，列链接（代码 / 文档 / 笔记）

## 待跟进
- 有哪些点需要后续深挖或验证
```

## 工作流程

### 第一步：读取数据库 URL

从 skill 目录下 `.env` 读取 `NOTION_CHAT_ARCHIVE_URL`。

### 第二步：判断是新建还是更新

- **新建**：用户说"归档/保存/存进对话录"，对话录里没有相关条目
- **更新**：用户说"复盘了 / 学完了 / 补充一下 / 改下重要度 / 把那条 xxx 更新一下"，且能定位到已有条目

如果不确定，先用关键词搜对话录库，找到候选再向用户确认。

### 第三步：萃取元数据（不要问用户，从对话里推断）

| 字段 | 推断方式 |
|------|---------|
| 标题 | 15 字以内概括对话核心 |
| 日期 | 今天（除非对话明显发生在其他日期） |
| 主题 | 见下方"主题分类判断" |
| AI 模型 | 当前模型，默认 `Claude Opus` |
| 相关项目 | 从对话里提到的项目名匹配现有选项 |
| 核心收获 | 1-2 句话提炼（必须是价值，不是动作） |
| 标签 | 多选，反映方法论特征 |
| 重要度 | 见下方"重要度判断标准" |

### 第四步：写入对话录库

使用当前环境可用的 Notion 工具（MCP 工具或其他方式）：

**新建场景**：
1. 用数据库 URL 拿到 schema 信息
2. 创建一条新记录，填入元数据
3. 在记录的 page 内容里按"内容模板"生成摘要

**更新场景**：见下方「更新工作流」

### 第五步：反馈结果

返回条目的 URL 给用户，并简述本次新增/修改了什么。

## 更新工作流

### 常见更新场景

| 场景 | 触发说法 | 修改字段 |
|------|---------|---------|
| 复盘完成 | "我已经复盘了 xxx 那条" | `是否复盘` → true |
| 价值重估 | "学完后发现这个其实更重要 / 没那么重要" | `重要度` |
| 补充收获 | "再加一条这个对话教我的东西" | `核心收获` 或 page 内容追加 |
| 加标签/项目 | "这条也跟 xxx 项目有关" | `标签` 或 `相关项目`（追加，不覆盖） |
| 续写延伸 | "刚才这个对话又有了后续，加进去" | page 内容追加新章节，标题加日期标记 |
| 改标题/分类 | "这个标题改成 xxx" | `标题` / `主题` |

### 更新原则

1. **多选字段是追加而不是覆盖**：标签、相关项目都是 multi_select，要先读现有值再合并新值
2. **核心收获允许迭代**：复盘后如果有更精炼的表达，可以重写；但保留原版到 page 内容作为对照
3. **page 内容追加新章节而非重写**：更新场景下，原有结构不动，在末尾加一个新的 `## 复盘补充（YYYY-MM-DD）` 或 `## 后续延伸（YYYY-MM-DD）` 章节
4. **变更说明**：反馈给用户的消息里要说明本次改了什么，例如"已勾上'是否复盘'，并在 page 末尾追加了复盘心得"

### 定位已有条目

更新前必须先准确定位条目，避免改错：

1. 优先按用户提供的关键词（标题、日期、主题）搜索
2. 找到多个候选时列出来让用户选
3. 找不到时不要新建，先问用户是否要新建

## 重要度判断标准（关键）

宁缺毋滥，默认给中，符合下列特征才给高：

- **⭐⭐⭐ 高**：改变认知模型 / 导向重大决策 / 暴露系统性盲区 / 提炼出可迁移的方法论
- **⭐⭐ 中**：学到具体方法论 / 解决棘手问题 / 产出可复用结构
- **⭐ 低**：参考性质 / 调试型对话 / 工具使用问答

**误区**：聊得开心 ≠ 重要。长对话 ≠ 重要。只看是否产生了可持续的价值。

## 主题分类判断

| 主题 | 特征 |
|------|------|
| 学习规划 | 制定学习路线、评估知识体系、设计学习方法 |
| 职业发展 | 转型、能力评估、长期方向讨论 |
| 技术方案 | 具体架构设计、选型、实现方案 |
| 产品设计 | 功能设计、用户体验、产品策略 |
| 调试排错 | 具体 bug 排查、问题定位 |
| 认知思考 | 哲学性讨论、思维模型、元认知 |
| 工具使用 | 某个工具的用法、配置、技巧 |
| 其他 | 不属于以上 7 类 |

## 选项扩展规则

select / multi_select 字段的值优先复用现有选项。**当现有选项无法准确表达时，允许新增**：

- 新增前先确认是否能匹配现有选项（不要因为措辞差异就新增）
- 新增的选项要符合该字段的语义层次（例如"主题"是高粒度分类，不要加细分）
- 新增后在反馈给用户的消息里说明："已新增 [字段] 的选项 [新值]"，便于用户审查
- 同义合并：如果发现新选项和现有选项语义重复，建议用户合并

特殊格式注意：
- 重要度的星号是 U+2B50（⭐），保持空格和符号一致
- 是否复盘默认 false

## 不做什么

- **不导出原文**：对话原文在 AI 工具里已经有了，这里只留摘要。如果用户坚持要原文，让他粘贴到记录 page 的内容里
- **不自动设为高重要度**：除非对话特征明显，默认中
- **不问用户元数据**：从对话里推断，只在无法判断时问
- **不强制复用旧选项**：当现有选项无法表达时，可以扩展（按上方"选项扩展规则"）

## 数据库入口

- URL：见 `.env` 里的 `NOTION_CHAT_ARCHIVE_URL`
- 视图：全部对话 / 按主题 / 高价值对话 / 待复盘
