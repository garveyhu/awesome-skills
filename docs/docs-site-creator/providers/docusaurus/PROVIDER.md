# Docusaurus Provider · 专业静态文档站

> 本文是 `docs-site-creator` 的 Docusaurus provider 手册(选型见上层 SKILL.md)。
> 适用:对外的产品 / 开发者文档、多读者群、要真搜索、要品牌级定制、会长大的文档。
> 形态对标 LangChain / React Native 官方文档:顶部模块标签 + 左侧栏 + 右侧本页目录 +
> 搜索 + 暗色模式,全部开箱内置。

## 心智模型

Docusaurus 3 = **markdown 内容 + 一份 config + 一层 CSS 覆盖**,构建出纯静态站。
三个对应关系记住就会用:

| 站上看到的 | 对应到 |
|---|---|
| 顶部一个模块标签 | `docs/<模块目录>/` + 一条 `docSidebar` navbar item |
| 左侧栏一个分组 | 模块目录下的子目录 + `_category_.json` |
| 一页文档 | 一个 `.md` 文件(frontmatter 定标题与排序) |

## Workflow

### 1. 规划信息架构(先于一切)

- **按读者要干的事切模块**(顶部标签),不按代码目录切。典型:使用指南 / 开发 / API 参考。
- 每模块内按子目录分组;每组 3~8 页,宁可多页薄页(300~800 字/页)。
- 模块首页固定叫 `overview.md`(`sidebar_position: 1`)。

### 2. 手工装配骨架(不用 create 向导)

`create-docusaurus` 向导要求空目录;实际场景 `docs/` 里往往已有内容(或多线并行在写),
所以**手写这几个文件再 `npm install`** 更稳:

```
site/
├── package.json
├── docusaurus.config.ts
├── sidebars.ts
├── docs/<模块>/...            # 内容(可先放占位页)
├── src/css/custom.css         # 主题 token 覆盖
├── src/pages/index.tsx        # 自定义首页(可选,React 随便写)
└── static/img/                # logo / favicon / 图片
```

`package.json` 依赖(实测可用的组合;版本随大版本更新):

```json
{
  "dependencies": {
    "@docusaurus/core": "^3.9.1",
    "@docusaurus/preset-classic": "^3.9.1",
    "@docusaurus/theme-mermaid": "^3.9.1",
    "@easyops-cn/docusaurus-search-local": "^0.52.1",
    "@fontsource/jetbrains-mono": "^5.2.5",
    "@fontsource/space-grotesk": "^5.2.5",
    "@mdx-js/react": "^3.0.0",
    "clsx": "^2.1.1",
    "prism-react-renderer": "^2.3.0",
    "react": "^18.3.1",
    "react-dom": "^18.3.1"
  },
  "devDependencies": {
    "@docusaurus/module-type-aliases": "^3.9.1",
    "@docusaurus/tsconfig": "^3.9.1",
    "@docusaurus/types": "^3.9.1",
    "typescript": "~5.6.2"
  },
  "scripts": { "start": "docusaurus start", "build": "docusaurus build", "serve": "docusaurus serve", "clear": "docusaurus clear", "typecheck": "tsc" }
}
```

`docusaurus.config.ts` 的关键块(中文站):

```ts
export default {
  title: '<站名>',
  url: 'https://<域名占位>',        // 上线前必换
  baseUrl: '/',
  onBrokenLinks: 'warn',            // 内容齐了以后收紧为 'throw'
  i18n: { defaultLocale: 'zh-Hans', locales: ['zh-Hans'] },
  markdown: { mermaid: true },
  themes: [
    '@docusaurus/theme-mermaid',
    ['@easyops-cn/docusaurus-search-local',
      { hashed: true, language: ['zh', 'en'], highlightSearchTermsOnTargetPage: true }],
  ],
  themeConfig: {
    navbar: {
      title: '<品牌名>',
      logo: { src: 'img/logo.png', width: 26, height: 26 },
      items: [
        { type: 'docSidebar', sidebarId: 'guide', position: 'left', label: '使用指南' },
        // …一个模块一条;右侧可放外链 / GitHub(用 className 配自定义样式)
      ],
    },
    mermaid: { theme: { light: 'default', dark: 'dark' }, options: { themeVariables: { /* 中性 slate,见 mermaid 规范 */ } } },
  },
};
```

`sidebars.ts` 全部用自动生成(内容目录即侧栏,不手维护清单):

```ts
export default {
  guide: [{ type: 'autogenerated', dirName: 'guide' }],
  // …一个模块一条
};
```

### 3. 内容约定

- 每页 frontmatter:`title` / `description` / `sidebar_position`;
  每个分组目录放 `_category_.json`:`{ "label": "分组名", "position": 2 }`。
- 提示用 `:::note` / `:::tip`,红线用 `:::warning`;mermaid 直接写 ```mermaid 围栏
  (按 mermaid 渲染安全规范作图,note 黄底在 custom.css 里兜底覆盖成中性色)。
- 站内链接两种都可:相对文件路径 `./sibling.md`(会被解析成路由)或绝对 URL
  `/docs/<模块>/<路径>`;跨模块优先绝对 URL。
- **`_` 开头的 md 是 partial**,不进侧栏不出页面——占位页别用下划线开头命名。
- 多线并行写内容时:外壳先建、每个内容目录先丢一篇占位页(navbar 的 docSidebar
  要求目录里至少有一篇文档,否则构建报错),内容齐后删占位。

### 4. 主题定制(把「Docusaurus 味」洗掉)

全部在 `src/css/custom.css`:先按 frontend-aesthetic 规约出**设计读数**(文档站取克制档,
V4 / M2 / D4 左右),冻结 token,然后覆盖 Infima 变量。要点:

- **亮暗两套各写全**:`:root { --ifm-* }` + `[data-theme='dark'] { --ifm-* }`。
  重点变量:`--ifm-color-primary` 五阶、`--ifm-background-color`、
  `--ifm-font-family-base`、`--ifm-navbar-*`、`--ifm-menu-color-*`、`--ifm-footer-*`。
- **白底专业脸是安全默认**:纯白 + 中性灰线 + 一个品牌强调色;暗色用中性近黑,别带色偏。
- **字体自托管**:`@import '@fontsource/<字体>/<字重>.css'`,中文走系统栈
  (PingFang SC / Source Han Sans),**绝不引 Google Fonts CDN**(国内不可达)。
- 顺手打磨的高回报细节:navbar 底部 1px 分割线 + backdrop blur、当前模块下划线指示条
  (`.navbar__link--active::after`)、搜索框圆角胶囊、侧栏子级左侧 1px 竖线、
  h2 下边线、表格 `display: table; width: 100%`、代码块细边去投影。
- 自定义首页 `src/pages/index.tsx` 是普通 React 页,配 CSS module;
  展示产品数据结构时用**真实代码片段**手工着色,不做假截图假终端。

### 5. 构建与验证(退出码 + 断链双门)

```bash
npm run build     # 退出码 0 且(收紧后)零 broken link 才算过
npm run serve     # 本地预览构建产物
```

- 内容定稿后把 `onBrokenLinks` 收紧为 `'throw'`,让断链直接红构建。
- 验证清单:四类页面各开一次(首页 / 文档页 / 搜索 / 暗色);搜索能中中文词;
  mermaid 亮暗两态都不糊。

### 6. 部署

产物是 `build/` 纯静态目录,任意静态托管直接放(自有服务器 / 对象存储 / Pages 类服务)。
部署在子路径时把 `baseUrl` 设为 `'/<子路径>/'` 再构建。

## 踩过的坑(每条都真实付过学费)

| 症状 | 原因与解法 |
|---|---|
| 文件明明存在,却报 broken link,构建产物里 href 残留 `.md` | **构建缓存吃了陈旧的文件清单**(外壳先建、内容后到的并行场景必中)。`npx docusaurus clear` 后重建即愈;凡内容文件与站点骨架分批落地,build 前先 clear |
| 链到 `static/` 下的独立子站(如 `/story/`)被判 broken link,点击还走 SPA 路由 | 链接写成 **`pathname:///story/`**——既跳过断链校验,又强制整页加载 |
| navbar 报找不到 sidebar | 对应内容目录是空的——autogenerated 的 docSidebar 要求目录里至少一篇非 `_` 前缀文档 |
| 占位页不进侧栏 | `_` 开头的 md 被当 partial 排除,占位页换正常文件名 |
| `docusaurus serve` 起来了,`curl 127.0.0.1` 却是 000 | 服务绑在 IPv6 localhost,用 `http://localhost:<port>` 访问 |
| mermaid 时序图 Note 黄底刺眼 | themeVariables 对 note 不稳定,必须 CSS 兜底:`.docusaurus-mermaid-container rect.note { fill/stroke !important }`(亮暗各一套) |
| 上线后资源 404 | `url` / `baseUrl` 还是占位值,或子路径部署没改 `baseUrl` |

## 组合模式:文档站 + 独立子站

站里要挂一个独立前端应用(如一篇自带视觉系统的叙事页 / demo app)时,**不要往
Docusaurus 里硬移植**——让它保持独立构建,产物挂进静态目录:

```
repo/
├── site/          # Docusaurus 本体
└── substation/    # 独立 Vite/React 应用,vite.config 设 base: '/story/'
```

根 `package.json` 编排:

```json
{ "scripts": {
  "build": "npm --prefix substation run build && rm -rf site/static/story && cp -r substation/dist site/static/story && npm --prefix site run build"
} }
```

站内所有指向它的链接用 `pathname:///story/`;子站里放一个「← 返回文档」链接(`href="/"`)。
两边样式零耦合,各自演进。
