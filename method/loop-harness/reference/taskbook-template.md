# 任务书模板（`00-任务书.md`）

> loop 的指挥中枢·**每轮第一必读**。复制下面骨架填空。原则：北极星要一句话说清、边界铁律要可执行、验证门要能跑、停止判据三类齐。**写完别让 loop 每轮重写它**（只战略级改·防语义漂移）。

```markdown
# 00 · <任务名> loop 任务书（指挥中枢）

> loop 每轮第一必读 → 选最高优先未完成项 → 多智能体推进 → 过验证门 → 更新台账 + 追加日志。
> 用户不喊停就继续，但触达「停止判据」要停下求人，不空转。

## 北极星（长期目标·一句话）
把 <X> 打磨成 <可识别的顶级状态>。**大胆推进、不受原结构限制**，只要服务北极星。

## ★ 验证门（命门·可执行的二元成功判据）
怎么客观看出「逼近了」：`<跑这个脚本/测试/真测/抽帧 → 看这个输出 = 过/不过>`。
每轮产出**跑它、贴真实输出、不报自评**。验证门定不出来 = 目标太模糊，先 brainstorm。

## 每轮审视方向（多智能体并行·防片面）
1. <方向一·建造员推进>
2. <方向二·审视员审查>
3. <方向三·对抗评估员挑刺>

## 关键授权 / 可用资源
- 可用 <真 API / key / 工具>（有成本·克制用·按需测·别批量烧）。key 读 <配置路径>·绝不硬编码/入库。

## 边界铁律（不可逾越·写死·agent 改不到）
- 服从 <项目宪章/红线>。
- 可做 <X> 但不可 <发布/注册账号/push/批量生产成品/不可逆操作>。
- 诚实标每项完成度 + 真验证结果 + 坑；做不到说做不到·不注水·负面结论照实记。
- 能力沉淀到该沉淀处（不散落一次性脚本）才算做完。

## 每轮流程
1. 读本任务书 + 台账 → 锚北极星 + 边界 + 验证门。
2. 选最高优先未完成项（优先级决策 ≠ 谁执行）。
3. 派多智能体（建造/审视/对抗评估）。
4. 落地 + 沉淀。
5. ★ 过验证门（贴真实输出）+ 对抗评估。
6. 更新台账 + 追加日志（倒序·date·诚实）。
7. 进度检测：无可验证新进展连续 2 轮 → 停下求人。否则下一轮。

## 停止判据（三类·缺一就有 runaway 风险）
- **success stop**：验证门过 + backlog 清。
- **failure stop**：不可恢复错 / 重试 2–3 次超限 / 显式判卡住 → 求人。
- **budget stop**：<轮数 / token / wall-clock> 硬上限兜底。

## 产出去哪
- 优化落地 → <对应代码/文件>。
- 开放项/优先级 → `01-台账.md`。
- 每轮记录 → `02-迭代日志.md`。
- 真测产物 → `<runtime 目录·gitignored>`。
```
