# 实战踩坑笔记（一个 100 轮 loop 跑出来的一手教训）

> 这些不是理论，是一个真跑了 100 轮的自主优化 loop 里**亲手踩过/验证过**的。比规则更重要的是这些「为什么」。

## 关于注水与诚实

- **对抗评估员防注水是真有效的，不是仪式**。100 轮里它第一刀就揪出：文档宣称的默认值与代码反向（声称「已锁 no-denoise」但代码默认相反）、宣称的「smootherstep 端点零加速度」实际跑的是另一条曲线、过冲值文档写 ≤8% 实测 9.8%、建了个 kit 但 0 个组件在用（shelf-ware）。**每条都被随后的代码实核证实**。教训：**派一个专门挑刺、默认怀疑、要证据引行号的对抗评估员，然后你亲自核它的指控**（python 实算 bezier 峰值、grep 代码默认值）——别轻信任何 agent 的自述。
- **shelf-ware 陷阱**：建了能力没人用 = 没做完。建了个入场 kit，对抗评估员问「0 生产组件采用却标已锁✅？」——对。于是真把它采用进一个生产组件证明它，才算数。**「能力沉淀成 skill / 被真正采用」才算做完，不是「代码写出来了」**。
- **负面结论照实记，是 learning 不是失败**。试了给离散气泡组件做词级对齐，渲出来死帧回归——诚实判负、撤回、把「词级 sync 适合连续自画不适合离散气泡」这条沉进锁。**一个诚实的负面结论，比假装成功有价值得多**，下次不会再撞。
- **主动修正自己的过度乐观**。日志里写过「余 8 个组件待采用 X」，后来读代码发现多数组件根本不适配 X——是过度乐观。**主动翻出来改**，别让一个乐观估计一直挂在台账上误导后续。

## 关于「不信自报·客观验证」

- **读代码再改，别凭记忆**。好几次以为某能力适用，一读代码发现不适配（入场 kit 不适配「生长/自画」类动画）——**读了才发现，没硬塞**。凭记忆推进多轮后容易漂，**周期性回锚任务书 + 读真代码**。
- **验证工具是「屏」不是「判官」**。死帧检测 -50dB 过度误报「慢但真在动」的细线绘制——抽帧才发现曲线在渐进画出、不是冻结。校准到 -62dB 才是真死帧门。**工具报了先抽帧/实核分辨，别盲信一个阈值就追幻影改好几轮**。
- **该实算就实算**。对抗评估员说过冲超标，没拿嘴信——python 把 cubic-bezier 峰值算出来（9.8%），坐实了再改。**数值类的事，LLM 别心算，跑出来**。

## 关于不漂移、不空转

- **周期性回锚任务书**。连做 7 轮组件级优化后差点 tunnel vision，回读任务书才发现：标着的 P0（接真 API）其实早完成了、当前真 frontier 是别的。**每隔几轮回锚一次北极星，别在局部最优里打转**。
- **诚实纠正 blocker 的表述**。反复说「某 key 是 blocked P0 等用户补」，用户一问才发现——能力早通了（另两条路径在跑），那个 key 只是可选的第三 provider。**把「锦上添花」说成「卡住的关键项」是表述注水，照实纠正**。
- **方法论本就对、是我违反了它**。出现死帧时想加「新规则」，一读方法论发现规则早有（单镜超 25s 必拆），是我手搓绕过了它。**先查方法论里有没有，多半「不是缺规则、是没遵守」**。
- **认识到 plateau + 递减**。地基搭扎实后，继续堆更多孤立件是递减回报；真正的「质变」往往卡在需要用户决策（触发一次重渲看效果）或更大的架构改。**诚实告诉用户「地基够了、剩下的要你拍板/要大改」，别假装还能靠小步快跑无限逼近**。

## 关于节奏与停止

- **一轮做一件、做扎实、过验证门、记日志**，比一轮塞五件强。每轮是个完整闭环（读→选→做→验→记），别贪。
- **停滞就停下求人，别空转**。连续没有可验证的新进展 = 信号，把「卡在哪、试了什么、要什么」抛给人，比硬跑烧 token 强。
- **重活（真渲/真测/大改）要克制**。100 轮里一个 turn 渲了 3 次片才得到干净版（前两次有 2s 片尾错、死帧回归）——**重活前想清楚会不会白渲，能在轻量验证里先排雷就别直接上重活**。

## 一句话总纲
**北极星 + 一个能跑的验证门 + 一个专门挑刺的对抗评估员 + 诚实记账（含负面结论） + 周期性回锚 + 停滞求人**——其余都是围绕这几件的文件外壳。把这几件做实，loop 就能长期高质量不漂移不注水。
