# scout · 勘探研究

## 何时选

大库摸底（结构 / 惯例 / 某能力现状）、方案调研、可行性验证、升级影响面评估。派活前吃不准范围时，先 scout 一轮再写 builder 任务书。

## 旋钮

- 模型 / effort：默认档；**只读**（不带 `--write`）；大范围勘探 `--background`

```
Agent(subagent_type: "codex:codex-rescue",
      prompt: "<问题清单> --background")
```

## 任务书骨架

1. **结构化问题清单**：要回答的具体问题逐条列（不是「帮我看看这个库」）
2. **范围**：从哪些目录 / 文件入手
3. **产出格式**：每个问题给「答案 + 证据（file:line）+ 置信度」；**要情报不要方案**——拍方案是 Claude 的活

## 姿态要点

- 问题越具体产出越有用；开放式问题先拆成可验证的小问题
- 报告里没证据的结论当传闻处理

## 验收衔接

抽查关键结论的 file:line 证据，核实后才进入方案设计。
