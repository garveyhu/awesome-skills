# detective · 疑难侦探

## 何时选

反复修不好的 bug、诡异的环境问题、要深挖调用链 / 时序的根因。Claude 自己试过一两轮没到根因就升 detective，别烂在原地。

## 旋钮

- 模型默认档 / `--effort high`
- **不带 `--write`**——先只读诊断；复杂案件 `--background`
- 根因确认后二选一：`--resume` 让它带 `--write` 修，或把根因转 [builder](builder.md) / [coder](coder.md) 修

```
Agent(subagent_type: "codex:codex-rescue",
      prompt: "<案情书> --effort high --background")
```

## 案情书骨架

1. **症状**：精确复现步骤、报错原文、期望 vs 实际
2. **已试清单**（最重要的一节）：全部已试过的假设和失败路径——防它重走老路
3. **环境事实**：版本、平台、配置里已确认的点
4. **产出格式**：分层输出——观察事实（带 file:line 证据）/ 推断（标不确定度）/ 开放问题 / 下一步建议

## 姿态要点

- 只要根因和证据，**不要它顺手改代码**
- 它的推断 Claude 必须独立复核证据再采信

## 验收衔接

根因必须能解释**全部**症状；按根因做最小验证实验确认后，才转修复任务。
