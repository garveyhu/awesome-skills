# coder · 普通确定性编码

## 何时选

规格明确、照施工图写就行的编码：按已定设计加一个接口、照既有模式补一个模块、写映射 / 配置 / 样板、补测试用例。判据一句话：**不需要做设计决策，正确答案基本唯一**。

不选：要做架构 / 设计判断（→ builder）；不需要理解代码的纯文本搬运（→ chore）。

## 旋钮

- `--model gpt-5.6-luna`（快省的 agentic 编码模型，确定性活的性价比档）；effort 不传（默认档）
- `--write` 必带；多文件批量可 `--background`

```
Agent(subagent_type: "codex:codex-rescue",
      prompt: "<任务书> --write --model gpt-5.6-luna")
```

## 任务书骨架

1. **锚 + 参照物**：点名「照哪个现有文件 / 模式写」（例：照 `src/foo/bar.ts` 的结构给 baz 写同款）
2. **输入输出给全**：接口签名 / 类型 / 文件清单直接写死，不留发挥空间
3. **done-gate**：一条验证命令
4. **提交规矩**同 builder（commitlint、一任务一提交）

## 姿态要点

- 规格给得越死越好；发现规格有歧义**要求它停下报告**，不许自行拍板
- 产出偏离参照模式 → `--resume` 指出参照点打回重来

## 验收衔接

done-gate + diff 快扫（重点看有没有越界发挥）。
