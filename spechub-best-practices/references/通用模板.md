# 通用规约模板

所有类型的规约共享的模板和自检清单。

---

## README.md 模板

回答："这个模块覆盖什么？消费方在阅读细节之前需要知道哪些共享约定？"

````markdown
# <模块名称> 规约文档

更新时间：YYYY-MM-DD
规约类型：API 对接 / 数据结构 / 业务流程 / ...

## 覆盖范围

本次交接涉及：
- 工作项 A
- 工作项 B
- ...

## 角色说明

| 角色 | 职责 |
|------|------|
| 生产方 | 谁产出了这份规约，负责什么 |
| 消费方 | 谁消费这份规约，要完成什么 |

## 通用约定

（根据规约类型填写。
  API 对接：鉴权、响应格式、分页、时间格式等；
  数据结构：命名规范、类型约定等；
  业务流程：术语表、角色定义等。
  参考对应分类模板获取具体建议。）

## 文件说明

### [CHANGELOG.md](./CHANGELOG.md)
增量更新时先看这个。

### [01-总览.md](./01-总览.md)
适合先看。（简述内容）

### [02-详细说明.md](./02-详细说明.md)
执行时边做边查。（简述内容）

## 关键决策记录

> 记录影响消费方实现的重要决策，说明"为什么这样设计"。
> 消费方 AI 理解了 why，就不会试图绕过或质疑这些设计。

- **决策 1**：简述。原因：...
- **决策 2**：简述。原因：...
````

## CHANGELOG.md 模板

核心设计：
- 条目按时间**倒序**排列（最新在最上面）
- 消费方 AI 从最新条目读到上次处理过的即可停止
- 每个条目必须包含：改了什么、为什么改、影响哪些部分、消费方具体待办

````markdown
# 变更记录

> 消费方 AI 拉取更新后，从本文件最新条目开始阅读即可了解所有变更，
> 无需重新扫描全量文档。

---

## [2026-03-26] 简述变更

**变更类型：** （见下方类型表）

**变更内容：**
- 具体改了什么

**变更原因：**
为什么要改。

**涉及文件和章节：**
- `02-详细说明.md` → 章节 X → 具体位置

**消费方需要做什么：**
- [ ] 待办 1
- [ ] 待办 2

---

## [2026-03-25] 初始版本

**变更类型：** 首次发布

**变更内容：**
- 完整规约文档

**消费方需要做什么：**
- [ ] 通读全量文档
````

### 变更类型参考

| 变更类型 | 含义 | 消费方影响 |
|---------|------|----------|
| 首次发布 | 全新规约 | 需通读全量文档 |
| 新增内容 | 增加了新的规约项 | 需对接新增部分 |
| 行为变更 | 已有规约项的规则/约束改变 | **高** — 已实现的部分可能需要修改 |
| 结构变更 | 数据结构、字段、枚举等改变 | 需更新对应实现 |
| 流程变更 | 执行顺序、状态流转、依赖关系改变 | **高** — 可能需要重构 |
| 文档修正 | 修正描述错误，实际规则未变 | 低 — 确认自己实现是否受影响 |

### 提交规范

git commit message 与 CHANGELOG 条目对应，便于 `git log` 快速扫描：

```
<变更类型>(<模块>): <简述>

例如：
行为变更(服务画像): reportClick 新增 carrierCode 必填校验
新增内容(医生端): 添加批量导出工作台数据接口
结构变更(服务画像): moduleCode 新增 GROWTH_RECORD
文档修正(医生端): 修正 workbench/detail 响应示例中的字段名
```

## 通用自检清单

所有类型的规约都应满足：

**完整性：**
- [ ] 覆盖范围已明确列出
- [ ] 生产方/消费方角色和职责已说明
- [ ] 所有规约项都有完整的输入输出规格
- [ ] 提供了具体示例（不只是抽象描述）
- [ ] 异常/错误场景有处理建议

**清晰度：**
- [ ] 无歧义的术语使用（或有术语表）
- [ ] 所有约束条件显式写出
- [ ] 负面约束已说明（"不要做 X"）
- [ ] 关键决策已记录并附原因

**增量协作：**
- [ ] CHANGELOG.md 已同步更新（非首次发布时）
- [ ] CHANGELOG 条目包含：变更类型、内容、原因、涉及章节、消费方待办
- [ ] commit message 遵循结构化格式

**实用性：**
- [ ] 提供了推荐执行顺序
- [ ] 每个文件都有更新时间戳
- [ ] 全局依赖关系清晰
